# 4. UI/UX Design System

### 4.1 Tailwind configuration (`tailwind.config.ts`)

A fairly conventional shadcn/ui-style Tailwind setup: `darkMode: ["class"]`, HSL CSS-variable-driven color tokens (`border, input, ring, background, foreground, primary, secondary, destructive, muted, accent, popover, card, sidebar.*`) plus **two custom tokens unique to this product**: `void` (`DEFAULT`/`deep`) and `sunrise`, `golden` (`DEFAULT`/`soft`) — signalling the cosmic/temple visual metaphor baked in at the design-token level, not just applied ad hoc in components. Fonts: `display: "Space Grotesk"`, `body: "DM Sans"`. Only two custom keyframes are registered at the Tailwind layer (`accordion-down/up`, `ticker-scroll`) — the vast majority of animation is instead defined directly in `index.css` (below), not through Tailwind's `theme.extend.keyframes`. Plugins: `tailwindcss-animate`, `@tailwindcss/typography`.

### 4.2 Global aesthetic (`src/index.css`, 851 lines)

The `:root` CSS variables (`:8-97`) establish what the file's own comments call a **"Sacred obsidian"** theme: *"black temple stone with deep gold undertone"* (`:9`). Concretely:
- Background `32 22% 3%` (near-black, warm-tinted) / foreground `42 38% 94%` (warm off-white).
- Primary `44 92% 58%` — a saturated "24k temple gold," explicitly commented as *"richer, more saturated, divine"* (`:19`).
- Extended custom tokens beyond the Tailwind base: `--void/--void-deep`, `--sunrise`, `--golden/--golden-soft/--golden-deep`, `--gold-leaf`, `--gold-ember`, `--glow-orange/--glow-gold` (`:42-52`).
- **Glass-morphism tokens**: `--glass-bg`, `--glass-border`, `--glass-highlight` (`:54-57`) back the `.glass`, `.glass-card`, `.glass-nav` utility classes (`:301-345`) used throughout `AppLayout` and cards — semi-transparent panels with `backdrop-filter: blur(16-32px) saturate(130-160%)`.
- **Per-time-slot "sky" gradients** (`:63-72`) — `--slot-morning-sky`, `--slot-midday-sky`, `--slot-evening-sky`, `--slot-night-sky`, each a multi-stop radial gradient plus a matching `--slot-*-accent` hue (morning=gold `43 96% 56%`, midday=blue `195 70% 55%`, evening=purple `285 55% 60%`, night=deep indigo `240 25% 55%`). This is the mechanism behind the ambient background changing color/mood across the four daily gates (§2.2's `GatePhase`) — likely consumed by `AmbientBackground.tsx`/`GlobalAmbientLayer.tsx`.
- **Shadow system**: `--shadow-glow`, `--shadow-glow-strong`, `--shadow-golden`, `--shadow-gilt` (an inset highlight + gold ring + drop shadow combo simulating gold-leaf inlay, `:77`), `--shadow-card`, `--shadow-elevated`.
- **Body pseudo-element ambient layers** (`:119-146`): `body::before` is a fixed, `z-index:0`, multi-radial-gradient "solar halo + altar glow + candle warmth at both edges" wash sitting behind all content; `body::after` is a `mix-blend-mode: overlay` **inline SVG `feTurbulence` gold-dust noise texture** at `opacity:0.06` — a genuinely bespoke touch (hand-authored SVG filter noise rather than a PNG asset) giving the whole app a faint "gilded dust" grain.
- **iOS/PWA ergonomics** baked into base layer: `-webkit-tap-highlight-color: transparent`, `overscroll-behavior-y: none`, forced `font-size: max(16px,1rem)` on inputs under `@supports (-webkit-touch-callout: none)` to prevent iOS auto-zoom (`:155-160`), `.safe-top/.safe-bottom/.safe-x` env(safe-area-inset-*) helpers (`:163-165`), and a `@media (display-mode: standalone)` override forcing pure black background for the installed-PWA case (`:168-170`).
- **Utility classes** (`:211-406`): `.text-gold-leaf` (animated shimmering gradient text, `gold-shimmer` keyframe cycling `background-position`), `.gilt-border` (a `mask-composite: exclude` technique to render a gradient-only border ring without a solid fill — the "temple inlay" look), `.glow-divine`/`.glow-altar` (layered `box-shadow` halos), `.atmosphere-amber`/`.atmosphere-amber-soft` (full-screen ambient backdrops explicitly commented as *"Prince-of-Persia atmospheric backdrop... Use on full-screen scenes (onboarding, hero, Elder, finalize)"* — a striking, specific creative-direction reference baked directly into a code comment, `:268-269`), `.skeleton-shimmer`, `.animate-breathe/.animate-app-breathe(-slow)` (slow scale/opacity pulses simulating literal breathing, used on orbs/ambient elements), `.progress-ring-track/.progress-ring-fill`.
- **`@keyframes`**: `breathe`, `app-breathe` (11s variant offset by `-3s` for a layered dual-breath effect), `float`, `pulse-glow`, `shimmer`, `star-twinkle`, `celebration` (scale bounce for milestone moments), plus a `@media (prefers-reduced-motion: reduce)` block (file truncated at line 500 in this pass, but present) respecting accessibility preferences.

### 4.3 Temple aesthetics (`src/pages/temple/*`)

The Temple sub-app has its own bespoke visual components layered on top of the shared design system:
- **`EcosystemMandala.tsx`** — a mandala-style radial visualization (likely the entry hub showing all masters/worlds arranged circularly, echoing the "sacred geometry" framing of the schema's `temple_presences`/`temple_calendar_events`).
- **`WorldDeepDive.tsx`** + **`worldData.ts`** — per-tradition ("world") detail views, backed by a static data file rather than a DB table (traditions/lineages are content, not user data).
- **`SamBranching.tsx`** — appears to implement a branching-dialogue/decision-tree UI (possibly for a specific guide character "Sam" or a generic branching-narrative primitive).
- **`EmberParticles.tsx`** — a particle-effect layer (embers/sparks) matching the "candle warmth" ambient theme from `index.css`.
- **`MiniBreath.tsx`** — a compact breathing-guide widget, reusing the breathe/app-breathe animation vocabulary at a smaller scale (e.g. embedded inside cards rather than full-screen).
- **`CustomCursor.tsx`** — a custom mouse cursor replacement, a common "immersive digital temple" touch for desktop users, reinforcing that the Temple section is treated as a more cinematic, less utilitarian surface than the rest of the app.

Database-side, the Temple's own encrypted journal (`temple_journal.is_encrypted`), tradition-preference toggle (`hindu/buddhist/universal/all`), and `reduced_motion` flag on `temple_user_state` show the aesthetic ambition is matched with real user-facing controls to dial the intensity down for accessibility/preference.

### 4.4 Cinematic system (`contexts/CinematicSessionContext.tsx`, `lib/cinematic/*`)

This is a **script-driven, level-adaptive guided-practice engine**, architecturally separate from the Guide chat (§5) even though both can appear inside a session.

- **Types** (`lib/cinematic/types.ts`): a `CinematicScript` is `{id, practice, label, defaultDurationSec, surface: "black"|"guru-bg"|"starfield", layers: CinematicLayer[]}`. Each `CinematicLayer` (`{layer:0-3, title, phases}`) represents a **depth of narration** — L0 is described as "beginner (most hand-holding)" through L3 "subtle (least narration, most space)" (`:50-52`). Each `CinematicPhase` has a `kind` (`arrival|deepen|checkpoint|integrate|close`) and an ordered array of `CinematicBeat` (`{text, holdMs, silent?}`) — i.e. **timed subtitle cards**, some of which are literally silent timed pauses (`silent: true`) for held breath/stillness moments. A `CinematicCheckpoint` mid-phase asks a `question` with two branching beat arrays (`onYes`/`onNotYet`) — matching the product-spec comment: *"single-tap [Yes]/[Not yet] checkpoints, adaptive branching, max 3-4 checkpoints per session, no typing"* (`:1-12`).
- **Registry** (`lib/cinematic/registry.ts`): three authored scripts currently exist — `kriyaEnergetic`, `pranayama`, `witness` (`:14-22`, sourced from `./scripts/*.ts`). `resolveLayer(script, userLevel)` (`:38-45`) maps a **constellation practice level** (0-7 scale) to a layer index: level ≥4 → L2, ≥2 → L1, else L0, capped to however many layers the script actually authored. `getUserPracticeLevel()` (`:51-63`) fetches the live level straight from `user_practice_constellation` by dynamically keying `${practice}_level` — a slightly loose (non-typed) but flexible pattern letting one query serve any practice type. `pickScript()` (`:65-85`) is the one-shot entry point: resolve script by id or practice → look up user level → return `{script, layerIdx}`.
- **Context/Provider** (`contexts/CinematicSessionContext.tsx`): mounted once in `AppLayout` (`AppLayout.tsx:19,303`), exposing `useCinematicSession()` with `play({scriptId?, practice?, userId?, guruImage?, guruName?, onComplete?, onExit?})` and `stop()`. `play()` calls `pickScript()`, stores the resolved `{script, layerIdx, ...}` in local state, and conditionally renders a `<CinematicSession/>` full-screen overlay component (`components/cinematic/CinematicSession.tsx`, not read in this pass) which is presumably the actual beat-by-beat player advancing `CinematicRunState` (`phaseIdx/beatIdx/pendingBranch/checkpointResponses`, defined in `types.ts:71-81`). Because this is a React Context (not a route), **any surface in the app — Guide, Practice, Witness — can trigger a full-screen cinematic sequence without navigating away**, and `onComplete`/`onExit` callbacks let the calling surface resume its own flow afterward.

### 4.5 Ambient backgrounds & animation

Several always-mounted "ambient" components sit underneath the routed content across the whole app (mounted in `App.tsx:324-327` and again per-layout in `AppLayout.tsx:338,385`): `GlobalStarfield`, `BreathingBackground`, `GlobalAmbientLayer`, `AmbientBackground` — a layered stack (star particles + slow "breathing" scale/opacity pulses + slot-based sky-color gradients) that together produce the game/temple-like living backdrop referenced throughout `index.css`. `ConsciousnessBusListener` (mounted alongside) is not a visual layer but a Realtime listener (§5.5) that can trigger ambient/toast reactions to server-pushed events (e.g. a companion "notices" something and the UI responds ambiently rather than via an explicit page navigation).
